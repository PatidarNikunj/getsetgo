# Quickstart: validate 001-oauth-login

## Prerequisites

1. Run `pnpm install`, then `pnpm infra:env` (this generates `AUTH_JWT_SECRET`), then `pnpm infra:up`.
2. In `apps/api/.env`, set:
   - `APP_ENV=development`
   - `AUTH_TEST_PROVIDER=enabled`
   - `AUTH_ALLOWLIST=test:e2e-*,test:alice,test:bob,<your email>`
3. Optional, for real providers:
   - Google: `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`, with the redirect URIs
     `http://localhost:3000/api/auth/google/callback` and
     `http://localhost:3001/api/auth/google/callback`.
   - GitHub: `GITHUB_OAUTH_APPS` with one OAuth app per origin (see
     [data-model](data-model.md#configuration-api-envts)). The setup steps go in `docs/backends.md`.
4. Run `pnpm --filter @getsetgo/api db:deploy`, then `pnpm dev`.

## Automated checks

```bash
pnpm turbo run lint typecheck test build
```

```bash
pnpm --filter @getsetgo/api test:e2e
```

```bash
pnpm test:e2e
```

What each suite covers:

- Unit tests:
  - allowlist matching
  - token rotation and reuse table
  - env refusal of the test provider in production
  - cookie attributes
  - `returnTo` validation
  - ai transcript sizes only
- API e2e: the full test-provider flow, IDOR attempts, rotation and reuse, sign out everywhere,
  account deletion (Postgres and Mongo).
- Web e2e: the auth suite and the signed-in notes suite, plus axe, for both apps.

## Manual scenarios (each app: http://localhost:3000 and :3001)

| #   | Story | Steps                                                                                        | Expected                                                                                        |
| --- | ----- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 1   | US1   | Open `/` signed out                                                                          | Redirected to `/sign-in`; provider buttons; no notes                                            |
| 2   | US1   | "Continue with test provider" → identity `alice` → Continue                                  | Lands on an empty notes page; header shows alice and "Test"                                     |
| 3   | US1   | As alice, create a note. In a private window, sign in as `bob`                               | bob sees no notes                                                                               |
| 4   | US1   | As bob, run `deleteNote`/`note`/`summarizeNote` with alice's note id (GraphQL via DevTools)  | `NOT_FOUND`, the same as a random UUID                                                          |
| 5   | US1   | Sign in as `mallory` (not allowlisted)                                                       | `/sign-in` with an "invite-only" message; no user row                                           |
| 6   | US1   | Press Cancel at the test provider                                                            | `/sign-in` with a "sign-in was cancelled" message                                               |
| 7   | US2   | Delete only the `__Host-gsg_at` cookie (DevTools), reload                                    | Still signed in; new cookies issued (server-side renewal)                                       |
| 8   | US2   | Copy the `__Host-gsg_rt` value; reload twice; send the old value to `POST /api/auth/refresh` | 401, and the browser is signed out on its next renewal (reuse detection)                        |
| 9   | US2   | Sign in on two browsers; "Sign out everywhere" in one                                        | Other browser loses access on its next renewal (≤ 15 min; force it by deleting `__Host-gsg_at`) |
| 10  | US2   | "Sign out", then press Back                                                                  | Sign-in page; notes not shown                                                                   |
| 11  | US3   | Account page → "Delete account" → confirm                                                    | Signed out with a confirmation; signing in as the same identity gives an empty account          |
| 12  | all   | Check the API logs and Sentry stand-in during 1–11                                           | No tokens, codes, emails or note text                                                           |
| 13  | all   | Keyboard-only through sign-in, menu, account and the dialog, in light and dark               | Visible focus, logical order, errors announced                                                  |
